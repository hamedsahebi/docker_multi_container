# MongoDB Integration Guide

## Overview

This application uses MongoDB as the database for storing user authentication data. The integration includes:

- **MongoDB 7.0** running in Docker containers
- **Mongoose ODM** for schema validation and data modeling
- **MongoDB Memory Server** for fast, isolated testing
- Proper connection management with health checks
- Separate databases for development, testing, and production

## Architecture

## Database Schema

### User Collection

```typescript
{
  _id: ObjectId,              // MongoDB auto-generated ID
  email: String,              // Required, unique, indexed, lowercase
  name: String,               // Required, user's display name
  googleId: String,           // Required, unique, indexed, Google OAuth ID
  picture: String,            // Optional, profile picture URL
  lastLogin: Date,            // Auto-updated on each login
  createdAt: Date,            // Auto-generated by Mongoose timestamps
  updatedAt: Date             // Auto-generated by Mongoose timestamps
}
```

**Indexes:**
- `email` (ascending, unique)
- `googleId` (ascending, unique)
- `createdAt` (descending)

## Environment Setup

### Development Environment

1. **Copy the example environment file:**
   ```bash
   cp .env.development.example .env.development
   ```

2. **Update MongoDB credentials (optional for dev):**
   ```env
   MONGODB_URI=mongodb://admin:devpassword123@mongodb:27017/sensor_monitoring_dev?authSource=admin
   ```

3. **Configure Google OAuth:**
   ```env
   GOOGLE_CLIENT_ID=your-google-client-id
   GOOGLE_CLIENT_SECRET=your-google-client-secret
   GOOGLE_CALLBACK_URL=http://localhost:3000/auth/google/callback
   ```

4. **Start the development environment:**
   ```bash
   docker-compose -f docker-compose.dev.yml up
   ```

### Production Environment

1. **Copy the example environment file:**
   ```bash
   cp .env.production.example .env.production
   ```

2. **⚠️ IMPORTANT: Update all security-critical values:**
   ```env
   # Use strong, unique passwords
   MONGO_ROOT_PASSWORD=your-secure-random-password-here
   
   # Generate secure random strings (use tools like openssl rand -base64 32)
   SESSION_SECRET=your-long-random-session-secret
   JWT_SECRET=your-long-random-jwt-secret
   
   # Update OAuth credentials for production domain
   GOOGLE_CLIENT_ID=your-production-google-client-id
   GOOGLE_CLIENT_SECRET=your-production-google-client-secret
   GOOGLE_CALLBACK_URL=https://yourdomain.com/auth/google/callback
   
   # Update CORS origin
   FRONTEND_URL=https://yourdomain.com
   ```

3. **Start the production environment:**
   ```bash
   docker-compose up -d
   ```

## Docker Compose Services

### Development (`docker-compose.dev.yml`)

```yaml
mongodb:
  image: mongo:7.0
  ports: ["27017:27017"]  # Exposed for local MongoDB tools
  environment:
    MONGO_INITDB_ROOT_USERNAME: admin
    MONGO_INITDB_ROOT_PASSWORD: devpassword123
    MONGO_INITDB_DATABASE: sensor_monitoring_dev
  volumes:
    - mongodb_data:/data/db      # Persistent storage
    - mongodb_config:/data/configdb
```

**Features:**
- MongoDB exposed on localhost:27017 for development tools
- Persistent volumes for data retention across restarts
- Health checks ensure database is ready before backend starts

### Production (`docker-compose.yml`)

```yaml
mongodb:
  image: mongo:7.0
  # NOT exposed externally - backend connects via Docker network
  environment:
    MONGO_INITDB_ROOT_USERNAME: ${MONGO_ROOT_USERNAME:-admin}
    MONGO_INITDB_ROOT_PASSWORD: ${MONGO_ROOT_PASSWORD}
    MONGO_INITDB_DATABASE: sensor_monitoring
  volumes:
    - mongodb_data:/data/db
    - mongodb_config:/data/configdb
```

**Security:**
- MongoDB NOT exposed to host network
- Uses environment variables for credentials
- Named volumes for persistent data

### Test (`docker-compose.test.yml`)

```yaml
mongodb-test:
  image: mongo:7.0
  tmpfs:
    - /data/db  # In-memory storage for fast tests
  environment:
    MONGO_INITDB_ROOT_USERNAME: admin
    MONGO_INITDB_ROOT_PASSWORD: testpassword123
```

**Features:**
- Uses tmpfs (RAM) for maximum test speed
- Automatically destroyed after tests complete
- Isolated from development and production databases

## Connection Management

### Database Configuration (`src/config/database.ts`)

```typescript
import mongoose from 'mongoose';

export async function connectDB(): Promise<void> {
  await mongoose.connect(process.env.MONGODB_URI);
  console.log('✅ MongoDB connected successfully');
}

export async function disconnectDB(): Promise<void> {
  await mongoose.connection.close();
}
```

**Features:**
- Automatic retry logic (built into Mongoose)
- Connection event listeners for monitoring
- Graceful shutdown on SIGINT/SIGTERM
- Environment-based connection strings

### Application Startup (`src/server.ts`)

```typescript
async function startServer(): Promise<void> {
  await connectDB();           // Connect to MongoDB first
  app.listen(PORT, () => {     // Then start Express server
    console.log(`Server running on port ${PORT}`);
  });
}
```

## Troubleshooting

### Connection Issues

**Problem:** Backend can't connect to MongoDB

**Solutions:**
1. Check MongoDB is running: `docker ps | grep mongodb`
2. Check health status: `docker inspect mongodb-dev | grep Health -A 5`
3. View MongoDB logs: `docker logs mongodb-dev`
4. Verify connection string in `.env.development`
5. Ensure backend waits for MongoDB health check

### Authentication Issues

**Problem:** Authentication failed

**Solutions:**
1. Verify credentials match in docker-compose and .env files
2. Check authSource parameter in connection string
3. Try connecting with mongosh to verify credentials

### Test Failures

**Problem:** Tests timeout or fail to connect

**Solutions:**
1. Increase Jest timeout: `jest.setTimeout(30000)`
2. Check MongoDB Memory Server is installed: `npm list mongodb-memory-server`
3. Clear Jest cache: `npx jest --clearCache`
4. Check test logs for connection errors

### Data Not Persisting

**Problem:** Data disappears after container restart

**Solutions:**
1. Verify named volumes are defined in docker-compose.yml
2. Check volume mount points: `docker inspect mongodb-dev`
3. Don't use `docker-compose down -v` (removes volumes)
4. Use `docker-compose down` (keeps volumes)

## Best Practices

### Security

✅ **DO:**
- Use strong passwords in production
- Keep MongoDB internal (not exposed to internet)
- Use environment variables for sensitive data
- Enable authentication (authSource=admin)
- Regularly backup production data

❌ **DON'T:**
- Commit .env files with real credentials
- Expose MongoDB ports in production
- Use default passwords (admin/admin)
- Store passwords in code
- Run without authentication

### Performance

✅ **DO:**
- Use indexes for frequently queried fields
- Limit query results with .limit()
- Use projection to select only needed fields
- Monitor slow queries
- Use connection pooling (Mongoose default)

❌ **DON'T:**
- Query without indexes on large collections
- Use .find() without filters
- Fetch all fields when you need few
- Open new connections per request
- Forget to close connections on shutdown

### Development

✅ **DO:**
- Use MongoDB Memory Server for tests
- Clear test data between tests
- Use separate databases for dev/test/prod
- Validate data with Mongoose schemas
- Handle connection errors gracefully

❌ **DON'T:**
- Test against development database
- Share databases across environments
- Skip schema validation
- Ignore connection errors
- Leave connections open after tests

## Migration from File-Based Storage

The previous implementation used JSON files for user storage. The MongoDB integration provides:

| Feature | File-Based | MongoDB |
|---------|-----------|---------|
| **Concurrency** | ❌ Race conditions | ✅ ACID transactions |
| **Scalability** | ❌ Limited | ✅ Horizontal scaling |
| **Querying** | ❌ Linear search | ✅ Indexed queries |
| **Relationships** | ❌ Manual joins | ✅ References & population |
| **Validation** | ❌ Manual | ✅ Schema validation |
| **Backups** | ❌ Manual copies | ✅ Built-in tools |
| **Performance** | ❌ Slow at scale | ✅ Optimized |

### Data Migration Script

If you have existing user data in JSON files:

```typescript
// scripts/migrate-users.ts
import { connectDB, disconnectDB } from '../src/config/database';
import { createUser } from '../src/services/userService';
import fs from 'fs/promises';

async function migrateUsers() {
  await connectDB();
  
  const data = await fs.readFile('./data/users.json', 'utf-8');
  const users = JSON.parse(data);
  
  for (const user of users) {
    try {
      await createUser({
        email: user.email,
        name: user.name,
        googleId: user.googleId,
        picture: user.picture
      });
      console.log(`✅ Migrated: ${user.email}`);
    } catch (error) {
      console.error(`❌ Failed: ${user.email}`, error);
    }
  }
  
  await disconnectDB();
}

migrateUsers();
```
